# Как MVP связан с ПР02–ПР04

Работа построена вокруг двух персон ПР02: Антон ищет исполнителя и отправляет бриф, Мира публикует 3D-работы и принимает заявки. Первым реализован полный путь поиска, просмотра, профиля и заявки; затем кабинет автора. Из отложенных идей ПР01 избраны реклама и платное продвижение как возможная модель дохода, но платёжные функции в учебный MVP не добавлены: они требуют прозрачной маркировки продвижения и отдельной проверки спроса.

| Экран / действие | User story | Данные из ПР03 и сохранение |
| --- | --- | --- |
| Каталог | US01 | `Artwork.workType`, `style`, `status`; опубликованные записи из `artworks` |
| Просмотр работы | US02 | `Artwork.technicalDetails`, `MediaFile` для обложки, превью и GLB |
| Профиль автора | US03 | `CreatorProfile.publicName`, `specialization`, `description`, `layoutConfig`; `Service.priceRange`, `estimatedDays` |
| Бриф заказчика | US05 | `Brief.title`, `description`, `budgetRange`, `desiredDeadline`, `authorProfileId`; `clientUserId` ставит API по токену |
| Мастерская / новая работа | US06 | `Artwork.title`, `description`, `workType`, `style`, `technicalDetails`; `MediaFile` сохраняет обложку и контент |
| Редактор профиля / услуг | US07 | `CreatorProfile.layoutConfig`; `Service.title`, `description`, `priceRange`, `estimatedDays`, `revisionRounds` |
| Вход и кабинет | Поддержка всех сценариев | `User.email`, `name`, `roles`, `status`; пароль уходит только в API и не хранится в клиентском коде |

В приложении больше трёх связанных экранов, есть переходы между ними, формы с сохранением в базе и более трёх тестовых записей. Сервер применяет матрицу доступа ПР03: гость видит опубликованное, заказчик — свои заявки, автор — свои работы и полученные заявки, администратор — панель модерации. Форма и сервер проверяют ввод, но сервер окончательно принимает решения о доступе и статусах. Сценарий отправки брифа соответствует потоку данных ПР03: запись появляется со статусом `submitted`, после чего отдельная загрузка добавляет референсы. Заказчик получает номер заявки, автор видит её во входящих.

Для отчёта ПР04: приложить скриншоты каталога, 3D-просмотра, профиля, формы брифа и мастерской; привести ссылки на оба репозитория и указать фактически затраченное время. Для доступа преподавателя к демо достаточно локального запуска по двум README; публичный сайт можно подключить позднее по указанным инструкциям хостинга.
